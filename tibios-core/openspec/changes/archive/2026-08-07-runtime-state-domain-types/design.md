# Design: runtime-state Data Family (Cluster Snapshot Domain Types)

## Technical Approach

Five plain value types in `crates/runtime-state/src/lib.rs`, single flat file, no submodules (`runtime-object`/`runtime-storage`/`runtime-scheduler` precedent). No traits, no Ports, no State Assembler pipeline. Dependency set stays exactly `runtime-primitives` + `runtime-object` + `runtime-scheduler` + `runtime-network`, zero external — already asserted by `runtime/tests/architecture_guard.rs:44-52` (`ALLOWED`) and `:101` (`EXTERNAL_ALLOWED`). `Cargo.toml` unchanged.

Verified against shipped code before pinning shapes:

- `runtime_primitives::{NodeId, AllocationId, WorkloadId}` all exist as ULID newtypes generated by `ulid_newtype!` (`identity.rs:96-116`) — each is `Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize, Default, Display` with a `new()` generator and a fallible `parse()`.
- `runtime_primitives::ObjectVersion` (`identity.rs:126-167`) is a private-field tuple struct over `u64` with exactly four methods — `initial()`, `next()`, `from_u64()`, `as_u64()` — plus `Default` delegating to `initial()`, and derives `PartialOrd, Ord, Hash`.
- `runtime_scheduler::Resource` (`lib.rs:15-50`) is `Debug, Clone, Copy, PartialEq, Eq` over `{ id: ObjectId, version: ObjectVersion, capacity: u64 }`, private fields, `const fn new/id/version/capacity`.
- `runtime_primitives::Timestamp` exists (`time.rs:12`) with `from_millis`/`now`/`as_millis` — relevant to D10 below.

## Architecture Decisions

### D1: `ClusterGeneration` is its own newtype, not a reused `ObjectVersion`

**Choice**: `pub struct ClusterGeneration(u64)` in `runtime-state`.
**Alternatives**: reuse `runtime_primitives::ObjectVersion`; mint a `ClusterGeneration` primitive in `runtime-primitives`.
**Rationale**: `ObjectVersion`'s own doc comment binds it to "a Logical Object's `ObjectId`" (`13-object-model.md`) — a Cluster Generation is not attached to any Object, it counts Runtime-wide events (`17-cluster-snapshot.md:57`). Reusing it would make the two counters interchangeable at the type level, which is exactly the confusion D2's guardrail exists to prevent. Promoting it into `runtime-primitives` is an architectural change (`runtime-primitives/src/lib.rs:5-8`: "Adding a primitive type is an architectural change... precedent is that adding `RuntimeId` required reopening `02-project-structure.md`") and it has exactly one consumer today — `runtime-state` owns it until a second domain needs it.

### D2: `ClusterGeneration` mirrors `ObjectVersion`'s full four-method surface, including `Ord`

**Choice**: `initial()`, `next()`, `from_u64()`, `as_u64()`, `Default` → `initial()`, and derived `PartialOrd, Ord, Hash`.
**Alternatives**: a bare `u64` field with only `new()`/`value()`; drop `Ord`.
**Rationale**: `17-cluster-snapshot.md:57` calls it a counter that *records* significant Runtime-wide events — recording means "advance from the current value", so `next()` and `initial()` are the operations the concept actually names, and the proposal explicitly asks for `ObjectVersion`'s shape. `from_u64`/`as_u64` come along for mirror-fidelity and because they are the only way a test (or a future wire converter) constructs a non-zero generation without chaining `next()` N times.

`Ord` is kept **and scoped in the doc comment**: ordering answers *"which observation is more recent"* — a legitimate observability/diagnostics question, the exact use `17-cluster-snapshot.md:57` sanctions. It must never answer *"is this Allocation Plan still valid"*; `17-cluster-snapshot.md:105` is explicit — "A Plan is invalidated only by changes to the objects it depends on — never by a global generation counter."

**Guardrail, enforced structurally**: no method, no field, and no free function in this crate pairs a `ClusterGeneration` with an `AllocationPlan`, a `Candidate`, or an admission decision. The invariant is unrepresentable, not merely documented. `next()` inherits `ObjectVersion`'s `self.0 + 1` overflow behavior verbatim; changing that is a `runtime-primitives`-wide call, not this slice's.

### D3: `HealthState` is `Healthy | Degraded | Unhealthy` — `Draining` is **excluded**

**Choice**: three variants.
**Alternatives**: the four-variant working default from exploration (`Healthy`, `Degraded`, `Draining`, `Unhealthy`); adding `Unknown`.
**Rationale**: this refines the exploration's working default on doc evidence found during design.

`16-scheduling-engine.md:71` attributes `Draining` to a *different* domain, by name: "it duplicated what **Membership's `Draining` state** already answers." `19-state-assembler.md:27,45` states the pipeline is Trust → Membership → Health → Resources, "each stage owned by exactly one domain, each answering exactly one question", and `:47`/`:95` forbid a stage re-deriving what an earlier, lower-volatility stage already established. Putting `Draining` inside `HealthState` makes the Health stage re-derive a Membership fact — a direct violation, and the same conflation `14-resource-model.md:94` warns about between Resources and Health ("must never be conflated").

The counter-evidence, `14-resource-model.md:94` ("a node can have ample Resources available and still be `Draining` or `Unhealthy`"), does not claim `Draining` *is* a Health value — that sentence contrasts Resource capacity against the other axes generally, and `22-networking.md:261` frames Networking/Membership/Health as three independent axes with Draining as the Membership-side example. The specific, attributive citation wins over the general one.

The three retained variants each have textual anchoring: `Healthy` (`16-scheduling-engine.md:46` "Healthy Nodes (Health)"), `Degraded` and `Unhealthy` (`14-resource-model.md:94` — "Health measures operational fitness (load, **degradation**, internal errors)" and the literal `Unhealthy`). `Degraded` is the adjectival form of a named Health concern, not an invention.

`Unknown` is rejected: nothing in any doc names an absent-observation state, and `19-state-assembler.md:53` already answers what happens when an observation cannot be made — the Snapshot is discarded, not published with a placeholder. A node with no Health observation does not appear in the Snapshot at all.

A `MembershipState` type (which would own `Draining`) is deferred to the Membership slice, not designed here.

### D4: `HealthState`'s doc comment declares itself inferred and revisable; no `Default`

**Choice**: the doc comment states, in the type itself, that unlike `ObjectType`/`ObjectLifecycle` (exhaustively enumerated in their owning docs) this variant set is **inferred from passing prose, not doc-mandated**, and that Health's real owning domain (`22-networking.md`'s `HealthChanged` event at `:413`, or a future security/membership crate) may revise it. No `#[non_exhaustive]` attribute — the crate has exactly one consumer today (`runtime-admission`, per the guard's `ALLOWED` table) and `#[non_exhaustive]` would force wildcard arms on a set we *want* to break loudly when it changes.
**No `Default`**: defaulting a Health observation would fabricate a fact the assembler never observed. `ClusterGeneration` gets `Default` (a fresh cluster genuinely starts at generation 0); `HealthState` does not.

### D5: `NodeState` = `NodeId` + `HealthState` + `Vec<runtime_scheduler::Resource>`

**Choice**: `NodeState { node: NodeId, health: HealthState, resources: Vec<Resource> }`, accessor `resources(&self) -> &[Resource]`.
**Alternatives**: a parallel `ResourceState` type; a single `Resource` instead of a `Vec`; keying off `ObjectId` + `ObjectVersion`.
**Rationale**: `14-resource-model.md` gives Resource to `runtime-scheduler` (no `runtime-resource` crate exists or should), and `runtime-state → runtime-scheduler` is an already-declared edge — "Resource summaries" (`17-cluster-snapshot.md`) reuses the shipped type directly. `Vec` because a Node offers many Resources (`16-scheduling-engine.md:73`'s cascade counts nodes *and* resources separately). `NodeId` because the shipped closed `ObjectType` enum has no `Node` variant, per the identity call already frozen in the proposal.

Accessor returns `&[Resource]`, not `&Vec<Resource>` — matching `runtime_worker::SecurityContext::grant_scope() -> &[String]` (`execution/context.rs:110`), the crate's existing precedent for a collection accessor.

### D6: `NodeState` carries no Trust, Membership, or capability field

**Choice**: exactly three fields, no `trusted: bool`, no `membership`, no `capabilities`.
**Rationale**: `19-state-assembler.md:45` — each pipeline stage is owned by exactly one domain. A `trusted` flag on `NodeState` would let `runtime-state` re-publish a Trust decision it only observes (`:73`: "Trust decisions remain owned by Trust; the State Assembler only observes their result"). Trust and Membership are pre-filters on *which nodes appear in the Snapshot at all* — a node in the `Vec<NodeState>` is trusted-and-a-member by construction, which is stronger than a field. Runtime capabilities are deferred per the proposal (same "intentionally partial" precedent as `runtime-scheduler`'s deferred GPU/CUDA taxonomy).

### D7: `AllocationSummary` is frozen at two fields and is `Copy`

**Choice**: `AllocationSummary { allocation: AllocationId, workload: WorkloadId }`, derives `Debug, Clone, Copy, PartialEq, Eq`.
**Alternatives**: add a status/phase, a `Lease`, a `Timestamp`, or the bound `Resource`.
**Rationale**: `15-allocation-model.md` owns Allocation lifecycle; `17-cluster-snapshot.md` asks the Snapshot for "Allocation summaries", not Allocation state. The two-ID pair answers the only question a planner asks of a Snapshot's allocation view — *what is already placed, and for whom*. Every excluded field is `runtime-allocation`-owned; carrying one here would duplicate ownership, the exact anti-pattern `19-state-assembler.md:85` lists. `Copy` because both fields are `Copy` ULID newtypes and the field set is deliberately frozen — same call as `runtime_scheduler::Resource`'s `Copy` (three `Copy` fields), and unlike `Candidate`, which was kept non-`Copy` precisely because it was expected to grow.

### D8: `ClusterSnapshot` is immutable by construction

**Choice**: `ClusterSnapshot { generation: ClusterGeneration, created_at: Timestamp, nodes: Vec<NodeState>, allocations: Vec<AllocationSummary> }`, private fields, one `new(...)` taking all four by value, read-only accessors (`generation() -> ClusterGeneration`, `created_at() -> Timestamp`, `nodes() -> &[NodeState]`, `allocations() -> &[AllocationSummary]`).
**Alternatives**: a builder with `add_node`/`add_allocation`; `&mut` accessors; wrapping in `Arc` inside the type.
**Rationale**: `17-cluster-snapshot.md:63` and `19-state-assembler.md:53` both require atomic publication — "either completely visible or not visible at all", "partially published Snapshots are forbidden". An incremental builder makes a partially-assembled Snapshot a representable value; a single all-fields constructor makes it unrepresentable. Same enforcement style as `runtime-storage`'s "no payload field".

`Arc` is deliberately **not** baked in: `19-state-assembler.md:61` places `Arc<Snapshot>` sharing at the publication layer, which is a future Port/composition-root concern. `ClusterSnapshot: Clone` lets any caller wrap it; owning the `Arc` here would presuppose a sharing strategy this slice defers.

### D9: no `serde` derives

Only `runtime-primitives` derives serde. The guard allowlists zero external dependencies for `runtime-state` (`architecture_guard.rs:101`), so serde is not even reachable. Same call as `runtime-scheduler`'s Slice 1.

### D10: `created_at` ships this slice; `snapshot_id` remains blocked — user-confirmed split

**Choice**: `ClusterSnapshot` carries `created_at: Timestamp` in addition to `generation` and the two `Vec`s; `snapshot_id` is still excluded.
**Rationale**: `17-cluster-snapshot.md:55` names an identity triple — "Every Snapshot owns a **Snapshot ID**, a **Creation Timestamp**, and a **Cluster Generation**." The two omissions this design originally proposed treating alike are not equivalent, and the user resolved them separately:

- `snapshot_id` stays **blocked**: no `SnapshotId` exists in `runtime-primitives` and `runtime-state` has zero allowed external deps, so no ULID can be minted. Adding the primitive reopens `02-project-structure.md` (`runtime-primitives/src/lib.rs:5-8`) — out of a data-family slice's authority.
- `created_at` ships: `runtime_primitives::Timestamp` already exists (`time.rs:12`), `runtime-primitives` is already a declared dependency, it adds no behavior and opens no new design question — it completes a field the owning doc already names. User's call: leaving it out for "triple symmetry" would force a second, avoidable field-addition slice later for zero benefit; the `(generation, created_at)`-as-de-facto-key risk is accepted as a documentation-level caveat rather than a reason to omit the field, since the doc comment states plainly that neither field is an identity substitute for `snapshot_id`.

`snapshot_id` is additive later, once the primitive lands.

### Derives

| Type | Derives | Why |
|------|---------|-----|
| `ClusterGeneration` | `Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash` + manual `Default` | Mirrors `ObjectVersion` exactly, minus serde (zero-external guard). `Ord` scoped by D2's guardrail |
| `HealthState` | `Debug, Clone, Copy, PartialEq, Eq` | Fieldless enum; matches `ObjectType`/`ObjectLifecycle`'s derive set. No `Default` (D4), no `Ord` — Health is not a rank |
| `NodeState` | `Debug, Clone, PartialEq, Eq` | Owns a `Vec` — not `Copy` |
| `AllocationSummary` | `Debug, Clone, Copy, PartialEq, Eq` | Two `Copy` ULID fields, frozen set (D7) |
| `ClusterSnapshot` | `Debug, Clone, PartialEq, Eq` | Owns two `Vec`s — not `Copy`; `Clone` enables caller-side `Arc` (D8). `Timestamp` is already `PartialEq`/`Eq`, so `created_at` costs nothing on the derive set |

## Data Flow

```
runtime-primitives ──(NodeId, AllocationId, WorkloadId)──┐
runtime-scheduler  ──(Resource)──────────────────────────┤
                                                         ▼
                              HealthState ──┐
                                            ▼
                              NodeId ──▶ NodeState ──────┐
                                                         ▼
        AllocationId + WorkloadId ──▶ AllocationSummary ─┤
                                                         ▼
                        ClusterGeneration ──▶ ClusterSnapshot
```

Composition is strictly one-way and acyclic; no type refers back to its container. `runtime-object` and `runtime-network` remain **declared but unexercised** this slice — `runtime-object` because no Snapshot field is content-addressed yet (D5 keys off `NodeId`), `runtime-network` because it is still a bare stub with no event types in code. Same "declared, not yet exercised" precedent `runtime-scheduler`'s Slice 1 set for `runtime-object`, and required by the guard's exact-set assertion.

Directionally, `runtime-admission → runtime-state` is the only declared consumer edge (`architecture_guard.rs:34`); it is a stub today, so nothing depends on this API yet.

## Interfaces / Contracts

```rust
use runtime_primitives::{AllocationId, NodeId, Timestamp, WorkloadId};
use runtime_scheduler::Resource;

pub struct ClusterGeneration(u64);
impl ClusterGeneration {
    pub const fn initial() -> Self;      // 0
    pub const fn next(&self) -> Self;
    pub const fn from_u64(value: u64) -> Self;
    pub const fn as_u64(&self) -> u64;
}
impl Default for ClusterGeneration { /* -> initial() */ }
// Ord: "which observation is more recent" ONLY — never plan validity (D2).

pub enum HealthState { Healthy, Degraded, Unhealthy }
// Inferred, not doc-mandated. `Draining` is Membership's, not Health's (D3).

pub struct NodeState { /* node: NodeId, health: HealthState, resources: Vec<Resource> */ }
impl NodeState {
    pub fn new(node: NodeId, health: HealthState, resources: Vec<Resource>) -> Self;
    pub const fn node(&self) -> NodeId;
    pub const fn health(&self) -> HealthState;
    pub fn resources(&self) -> &[Resource];
}

pub struct AllocationSummary { /* allocation: AllocationId, workload: WorkloadId */ }
impl AllocationSummary {
    pub const fn new(allocation: AllocationId, workload: WorkloadId) -> Self;
    pub const fn allocation(&self) -> AllocationId;
    pub const fn workload(&self) -> WorkloadId;
}

pub struct ClusterSnapshot {
    /* generation: ClusterGeneration, created_at: Timestamp,
       nodes: Vec<NodeState>, allocations: Vec<AllocationSummary> */
}
impl ClusterSnapshot {
    pub fn new(
        generation: ClusterGeneration,
        created_at: Timestamp,
        nodes: Vec<NodeState>,
        allocations: Vec<AllocationSummary>,
    ) -> Self;
    pub const fn generation(&self) -> ClusterGeneration;
    pub const fn created_at(&self) -> Timestamp;
    pub fn nodes(&self) -> &[NodeState];
    pub fn allocations(&self) -> &[AllocationSummary];
}
// created_at completes 17-cluster-snapshot.md:55's identity triple alongside
// `generation`; `snapshot_id` remains the one still-blocked field (D10).
```

Every constructor and accessor carries `#[must_use]`, matching `runtime-scheduler`/`runtime-worker`. Constructors taking a `Vec` are plain `fn`, not `const fn` — same as `runtime_worker::SecurityContext::new` (`execution/context.rs:83`). All fields private; `missing_docs = "warn"` (workspace lint) means every public item and every enum variant needs a doc comment.

## Testing Strategy

Strict TDD: one failing test per behavior before its implementation. All tests live in a single `#[cfg(test)] mod tests` at the bottom of `lib.rs` (`runtime-scheduler` precedent — no `tests/` directory, since there is no Port to drive).

| Layer | What to Test | Approach |
|-------|--------------|----------|
| Unit | `ClusterGeneration::initial()` is `0` | `assert_eq!(ClusterGeneration::initial().as_u64(), 0)` |
| Unit | `next()` advances by one and is pure (calling it twice on the same value yields the same result) | Same module |
| Unit | `from_u64`/`as_u64` round-trip | Same module |
| Unit | A later generation compares greater than an earlier one | `assert!(later > earlier)` — locks the D2 ordering semantics |
| Unit | `Default` equals `initial()` | Same module |
| Unit | `HealthState` variants are distinct and `Copy` | `assert_ne!` across the three; pass by value twice |
| Unit | `NodeState` construction/accessors round-trip, including a multi-`Resource` node | Same module; build `Resource`s via `Resource::new(ObjectId::new(), ObjectVersion::initial(), n)` |
| Unit | `NodeState` with an empty resource list is representable (a healthy node offering nothing) | Same module |
| Unit | `AllocationSummary` construction/accessors round-trip | Same module |
| Unit | `ClusterSnapshot` construction/accessors round-trip with populated `created_at`, `nodes`, and `allocations` | Same module |
| Unit | An empty `ClusterSnapshot` (no nodes, no allocations) is representable | Same module — an empty cluster is a valid *complete* observation, distinct from a partial one |
| Unit | `ClusterSnapshot` equality is structural (two snapshots built from equal parts are equal) | Same module — the property publication-atomicity checks will later rely on |
| Static | No `ClusterGeneration` API pairs a generation with a plan/candidate/decision (D2) | Review-only, structural |
| Static | No `ResourceState`, no `WorkloadState`, no `MembershipState`, no `snapshot_id` field | Review-only, structural |
| Static | No public trait; no mutator or `&mut` accessor on `ClusterSnapshot` | Review-only + `cargo clippy --all-targets -- -D warnings` |
| Static | Dependency set unchanged, zero external | `runtime/tests/architecture_guard.rs` (existing, no edit) |

Gate: `cargo test -p runtime-state`, `cargo test --workspace`, `cargo clippy --all-targets -- -D warnings`.

No integration or E2E layer — no Ports, no transport, no assembler exist yet.

## Migration / Rollout

No migration. Purely additive: `runtime-state` currently exports nothing, and its only declared consumer (`runtime-admission`) is a stub. Rollback is `git revert` of a single commit. The State Assembler pipeline, `Cluster Summary` (Admission's coarser view), and any Port are separate future changes, not designed here.

## Open Questions

Carried forward, deliberately unanswered:

1. **`snapshot_id`** — blocked on minting a `SnapshotId` primitive, an architectural change to `runtime-primitives`/`02-project-structure.md`. Additive once the primitive lands.
2. **`created_at: Timestamp`** — resolved. User confirmed shipping it this slice (D10): not blocked, adds no behavior, and completing `17-cluster-snapshot.md:55`'s field is lower cost than a future field-addition slice.
3. **`HealthState`'s real owner and variant set** — inferred here (D3/D4); `22-networking.md`'s `HealthChanged` event or a future membership/security crate may revise it. `Draining` needs a `MembershipState` home.
4. **Cluster topology and Runtime capabilities** — listed in Snapshot Contents with zero doc elaboration; deferred.
5. **Immutable-whole vs. incremental Delta snapshots** — `19-state-assembler.md:65` names incremental assembly as future work; D8's all-fields constructor does not preclude it.
6. **State Assembler invariants** (Trust → Membership → Health → Resources) — a future behavior slice.
